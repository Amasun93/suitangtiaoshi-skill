# suitangtiaoshi-skill

面向教师的课堂工作 Skill，包含学生项目素材批量整理、基于真实课堂观察的每日家长回课，以及学生答辩准备交接。老师不需要编写命令或提示词模板，只需提供材料或如实口述学生情况。

学生最终答辩由 `idealab-student-skills` 作为唯一入口完成；本 Skill 负责先把本地材料归档清楚并说明缺项，避免教师端和学生端维护两套不同规则。

## 能力概览

| 能力 | 作用 |
|---|---|
| 学生材料整理 | 扫描原始素材，识别学生、项目和材料类别 |
| 归档预演 | 先列出建议目标、判断依据、重复项和待确认项 |
| 安全归档 | 老师确认后复制材料、统一命名、保留代码目录并记录 SHA-256 |
| 档案检查 | 检查每名学生的目录、主要材料和待确认内容 |
| 每日家长回课 | 根据 D1—D7 课程和老师口述生成回课草稿 |
| 事实边界 | 不猜测学生归属、完成程度、实验结论或项目效果 |

## 老师怎么用

这个 Skill 不要求老师先把材料整理成最终档案结构。老师只要把“原始材料、学生项目清单、正式档案位置”交给 AI，AI 就能先扫描并生成分类预演。

### 第一步：准备三类输入

#### 1. 原始素材目录

把本次要整理的材料集中放在一个素材目录中。可以是老师收来的文件、学生提交的文件，也可以是两者混合。

原始素材不要求提前按标准目录摆放，可以出现这些情况：

- 按学生分文件夹；
- 按日期、来源或发送人分文件夹；
- 所有学生材料混在一个文件夹中；
- 代码、图片、视频、PPT、压缩包分散在不同子目录中。

但原始素材目录应当和正式档案目录分开，不要把已经生成的正式档案再次作为本次素材输入。

#### 2. 学生—项目清单

AI 需要知道每名学生对应哪个项目。可以提供现成的 JSON 清单，也可以直接把学生名单和项目名称发给 AI，让 AI 先整理成清单。

每名学生至少需要：

- 正式姓名；
- 项目名称。

如果材料中使用了小名、旧姓名、项目简称或旧项目名，也一起提供，作为别名。这样 AI 才能在文件夹名和文件名中找到正确的学生。

#### 3. 正式档案位置

告诉 AI 整理后的正式档案要放在哪里，例如：

- 项目交付档案；
- 某个班级的学生项目档案目录；
- 一个新的空档案目录。

如果这批材料来自老师预开发、学生制作或 AI 生成，也一并说明；来源不清楚时可以说“混合来源”或“待确认”。

### 第二步：材料怎么放更容易识别

材料不需要老师逐个改名，但文件夹名和文件名中最好保留学生名、项目名或材料关键词。

常见关键词包括：

- 开题、项目方案、立项；
- 项目手册、学习手册；
- 代码、程序、源码、固件；
- 图纸、结构图、原理图、模型；
- 功能、实现、效果、运行；
- 实验、测试、测量、数据；
- 原型、装置、成品；
- 制作、焊接、组装、调试；
- 演示视频、项目视频、讲解视频；
- 答辩、路演、展示；
- 交接单、签收单；
- 学生论文、研究日志。

代码目录可以继续保留原来的内部结构，不需要为了归档拆散文件。图片没有明确用途时，AI 会先放入待确认或参考资料，等待老师判断。

### 第三步：把什么内容交给 AI

可以直接把素材文件夹附在对话中，或告诉 AI 本地路径，同时提供：

1. 班级或项目批次；
2. 学生—项目清单；
3. 正式档案目录；
4. 材料来源；
5. 下面这句话作为执行要求：

> 请使用 suitangtiaoshi-skill 整理这批学生项目材料。先扫描并生成预演清单，识别学生、项目和材料类别；不确定的地方集中问我；没有得到我确认前，不要复制、移动或删除文件。

AI 会主要根据文件夹路径、文件名、扩展名、学生别名和项目别名进行识别。它不能仅凭文件名可靠判断照片内容、视频清晰度或项目是否运行成功，因此这些情况会保留为待确认或交给老师查看。

### 第四步：完整使用流程

1. 老师提供素材目录、学生—项目清单和正式档案位置。
2. AI 扫描材料，生成每个文件的学生、类别、目标位置和判断依据。
3. AI 输出预演结果，区分可归档、重复和待确认。
4. 老师集中回答问题，例如“这几段视频都是老师讲解版”“这几张图片属于制作过程”。
5. AI 更新预演结果，老师检查数量和目标位置。
6. 老师明确说“确认归档，可以执行”后，AI 才进行正式复制。
7. AI 生成归档执行结果、去重记录和每名学生的整理记录。
8. AI 再检查每名学生的档案目录和缺项，老师最后查看实际文件。

正式归档前不会修改原始素材。归档脚本只复制文件，不移动和删除源文件。

### 每日回课需要提供什么

生成家长回课时，不需要提供项目材料目录，只需要提供：

- D1—D7 中的日期或当天课程主题；
- 今天实际完成了什么，哪些计划没有完成；
- 每名学生的真实表现，口述即可；
- 老师是否提供了帮助；
- 已确定的下一步安排。

可以要求 AI 生成整班回课，也可以只润色一名学生的一段表现。AI 会整理语言，但不会补写没有确认的完成程度、实验结论、进度百分比或“独立完成”等判断。

## 材料整理时AI应该怎么做

1. 读取本 Skill 的 `SKILL.md` 和 `references/archive-schema.json`。
2. 找到老师提供的素材目录、正式档案目录和学生项目清单。
3. 扫描材料，识别对应学生、项目、材料类别和建议文件名。
4. 先生成整理预演清单，不立即写入正式档案。
5. 把不确定项用简单中文选项询问老师。
6. 根据老师回答更新判断，并重新生成预演清单。
7. 汇总将复制、跳过重复和仍待确认的数量。
8. 只有老师明确确认后才正式归档。
9. 完成后检查结果，并说明每名学生新增了哪些材料、还有哪些缺项。

AI 不应把技术操作转交给老师。若需要修正规则，由 AI 自己生成覆盖文件并重新预演。

## AI 需要询问的情况

- 文件无法唯一对应某名学生。
- 一个学生存在多个相近项目名称。
- 图片无法判断是功能、实验、原型还是制作过程。
- 视频无法判断是老师讲解版还是学生正式版。
- PPT 无法判断是开题方案还是答辩 PPT。
- 文件名与内容、目录或项目明显冲突。

同类问题应合并询问。例如：

> 这 6 段视频都来自老师预开发材料包。是否统一作为“老师讲解版”归档？

不要连续询问 6 次相同问题。

## 整理结果

每名学生使用以下档案：

```text
随堂调试-学生姓名-项目名称/
├─ 01 开题书/
├─ 02 学生项目手册/
├─ 03 项目图纸/
├─ 04 项目代码/
├─ 05 项目关键性图片/
├─ 06 答辩材料/              # 答辩PPT与答辩视频
├─ 07 项目视频/
├─ 08 项目装置交接单/
├─ 09 可选-学生论文/
├─ 10 研究日志/
└─ 99 待确认/
```

Skill 会保存预演清单、SHA-256 去重结果和每名学生的归档操作记录。

## 安全规则

- 只复制，不移动或删除源文件。
- 不覆盖已有材料。
- 相同内容不重复复制。
- 未确认的学生归属不写入正式档案。
- 未明确确认前不执行正式归档。
- “已经归档”只表示文件完成了整理和复制。
- 学生名单、项目材料和密钥不应上传到 Skill 仓库。

## 给 AI 的命令参考

通常由 AI 自动执行，老师不需要手动输入。

```bash
# 生成预演
node scripts/organize-materials.mjs plan --intake "待整理素材" --archive-root "项目交付档案" --roster "学生项目清单.json" --origin unknown --output "整理预演.json"

# 老师确认后正式归档
node scripts/organize-materials.mjs apply --plan "整理预演.json" --confirm

# 检查档案缺项
node scripts/organize-materials.mjs audit --archive-root "项目交付档案" --roster "学生项目清单.json" --output "档案检查.json"
```

材料整理模块负责命名、复制、去重、记录和缺项检查。图片质量、视频清晰度和项目事实不由脚本判断，需要老师自行查看。

## 每日回课

- 保留D1—D7公共回课模板，按当天真实课堂情况调整。
- 老师口述学生表现后，AI只整理语言，不改变完成程度和责任边界。
- 姓名以正式名单为准；不把同音字、生僻字自动改成常见姓名。
- 个性化反馈应包含具体进展、可观察行为、肯定和必要的改进建议，不能只写空泛表扬。
- 老师提到分心、耐心不足或依赖提醒时，使用客观、柔和的行为描述，不删除这些信息，也不给学生贴标签。
- 未经确认，不写“功能达标”“完整实现”“独立完成”或进度百分比。
- 默认只输出草稿，不自动发送家长群，也不自动写入学生档案。
