# 每日家长回课

## 定位

保留D1—D7公共回课模板，只把其中“学生今天的表现”替换为教师事实驱动的个性化段落。老师可以口述不完整、重复或带语气词的观察；AI负责整理语言，不改变事实强度。

## 两层内容

### 公共回课

说明：

1. 今天学习了什么。
2. 为什么这样设计课程。
3. 学生能获得什么，以及课程期待带来什么。

公共回课同一班级可以复用，但必须以当天实际完成情况覆盖预设模板。模板中的事项不能直接视为完成事实。

### 个性化表现

把教师对一名学生的原始口述润色为一段自然反馈。默认以“[姓名]同学今天……”开头，不使用“宝贝”“妈妈您好”等称呼，除非老师另有要求。

个性化段落优先包含：

- 学生实际完成的任务、功能、作品或材料；
- 一个可观察的过程行为，例如主动重试、解释逻辑、短暂休息后继续、接受帮助、改善分心；
- 值得肯定的能力或变化；
- 一个真实且柔和的改进方向；
- 已确认的下一步安排或期待。

不是每段都必须凑齐五项。老师没有提供不足时，不制造缺点；老师提供了不足时，不为了“好听”而删掉。

## 输入

生成完整回课时优先收集：

- D1—D7中的哪一天、日期和当天实际课纲；
- 上午、下午实际完成事项和临时调整；
- 学生名单与项目名称；
- 每名学生的原始观察；
- 次日已经确定的安排；
- 可选的用餐、休息、采访、拍摄等生活或课堂情况。

仅润色个性化表现时，只需要准确姓名和老师的原始口述。不得强迫老师填写表格。

## 事实优先级

1. 老师当前明确确认的事实。
2. 随堂老师的现场观察和实际文件、照片、视频。
3. 学生研究日志中的真实口述。
4. 当天课程计划。
5. 七天模板。

信息冲突时按以上顺序处理。姓名必须以正式学生名单为准；例如语音识别把生僻字转成常见同音字时，不能沿用错误写法。

## 忠实润色约束

- “整体效果不错”不能升级为“运行效果达标、方案验证通过”。
- “基本完成核心逻辑”不能升级为“完整实现全部预设功能”。
- “在老师帮助下实现”必须保留老师参与，不能写成学生独立完成。
- “休息后继续推进”可以写成调整状态后继续，但不能无依据升级为“韧性十足”。
- “今天没有玩游戏”可柔和表达为专注力或自我管理有进步，但不能直接改成“全程高度专注”。
- 未经老师确认，不使用项目进度百分比、实验结论、功能稳定、独立完成、显著提升等判断。
- 不使用“功能落地、助力、综合表现亮眼、更加闪耀”等宣传式套话。
- 不根据性别猜测“他/她”；名单没有可靠信息时优先使用姓名或“孩子”。

## 柔和批评

批评只描述行为和下一步，不给学生贴性格标签。

推荐结构：

> 已经取得的具体进展 + 过程中真实出现的困难或不足 + 可以怎样做得更好 + 对潜力的判断。

示例：

原始口述：

> 今天任务完成不少，但是中间有点坐不住，催了几次才继续。理解其实挺快的。

润色：

> 张同学今天完成了模型调整和程序初测，对新任务的理解速度较快。过程中有几次注意力转移，在老师提醒后能够重新回到任务中。后续如果能更主动地保持专注、减少等待提醒，这份理解力会更充分地转化为项目成果。

## 输出

### 完整回课

使用 [seven-day-feedback-templates.md](seven-day-feedback-templates.md) 中对应日期的公共结构，并将个性化占位替换为润色后的学生表现。不要为每名学生重复创作不同的公共课程事实。

### 仅润色学生表现

只输出一段可直接替换占位符的文字，不重复公共课程内容，不额外生成多个风格版本，除非老师要求。

### 批量模式

- 先形成一份经老师确认的班级公共内容。
- 再逐名生成个性化段落。
- 姓名、项目和观察无法唯一对应时，将该生列入“待确认”，不猜测。
- 同一学生前后两条观察存在冲突时，保留冲突并询问老师。

### 教师核对

草稿后仅在必要时附“待确认”：姓名、完成程度、老师参与、功能结果或下一步安排。没有疑点时不增加核对负担。

回课默认只在对话中输出。保存到学生档案或发送到家长群都需要老师另行明确授权。
